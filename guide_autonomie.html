01 — Fondamentaux

Anatomie d'une librairie Python

Une librairie est un ensemble de fichiers .py organisés pour être réutilisés dans d'autres projets. Quand tu écris import beau_graphique, Python cherche un fichier beau_graphique.py (module) ou un dossier beau_graphique/ avec un __init__.py (package).

Module vs Package — la distinction clé

Un module = un seul fichier .py. Un package = un dossier avec plusieurs modules et un __init__.py. beau_graphique utilise des modules plats — chaque fichier est autonome, pas de sous-dossiers nécessaires :

src/beau_graphique/
  beau_graphique.py   # → import beau_graphique
  narratif.py         # → import narratif
  pipeline.py         # → import pipeline
  themes.py           # → import themes

pyproject.toml — le fichier d'identité

C'est le fichier que pip lit pour savoir comment installer la librairie. Les lignes importantes :

[project]
name = "beau-graphique"        # nom pip (tirets acceptés ici)
version = "0.1.0"
dependencies = ["matplotlib>=3.5", "numpy"]

[tool.setuptools]
py-modules = ["beau_graphique", "narratif", "pipeline", "themes"]
#           ↑ liste des fichiers .py à installer

[tool.setuptools.package-dir]
"" = "src/beau_graphique"
#   ↑ où pip les trouve dans ce repo
Règle Si tu ajoutes un nouveau fichier .py (ex. export.py), ajoute son nom à py-modules et relance pip install -e ..

pip install -e . — le mode développeur

Le flag -e signifie editable. Pip crée un lien symbolique vers ton dossier source. Résultat : chaque modification dans les fichiers .py est immédiatement visible dans ton notebook ou script — sans réinstaller.

# À faire une seule fois, dans le dossier du projet
pip install -e .

# Vérification
python -c "import beau_graphique; print('OK')"

Comment Python résout un import

  1. Il cherche dans les modules intégrés (os, sys…)
  2. Il cherche dans sys.path — une liste de dossiers qui inclut le site-packages de ton environnement
  3. Il charge le fichier .py et le met en cache dans sys.modules
  4. Les imports suivants du même module retournent le cache — le fichier n'est pas relu
Piège notebook Si tu modifies beau_graphique.py pendant qu'un notebook est ouvert, il faut relancer le kernel pour que les changements soient pris en compte. Le cache module ne se rafraîchit pas seul.
02 — Fondamentaux

Architecture de beau_graphique

Convention public / privé

En Python, un nom commençant par _ est privé — usage interne. Tout le reste est l'API publique que les utilisateurs appellent. Cette convention n'est pas imposée par le langage, mais elle est universellement respectée.

NomVisibilitéRôle
barres(), ligne()…PublicAPI utilisateur — fonctions de graphiques
_TPrivé (dict)Thème actif : 6 clés de couleurs sémantiques
_new_fig()Privé (fn)Crée figure + ax avec le bon fond
_appliquer_background()Privé (fn)Applique fond/transparence sur fig et ax
_finaliser()Privé (fn)Ajoute titre, sous-titre, note, grille, marges
PALETTEPublic (list)8 couleurs du style actif
_COULEUR_HAUT / _BASPrivé (str)Vert/rouge sémantiques indépendants de PALETTE

Flux d'une fonction typique

Toutes les fonctions publiques suivent le même enchaînement en 4 étapes :

def barres(categories, valeurs, titre="", ..., background=None):

    # 1 — Créer (ou réutiliser) la figure avec le fond correct
    fig, ax = _new_fig(figsize, ax, format, background)

    # 2 — Dessiner avec matplotlib
    ax.bar(x, valeurs, color=PALETTE[0 % len(PALETTE)])

    # 3 — Finaliser (titre, note, grille, marges)
    _finaliser(ax, titre, sous_titre, xlabel, ylabel, note)

    # 4 — Toujours retourner (fig, ax)
    return fig, ax

Le dict _T — thème actif

C'est l'état global qui contrôle toutes les couleurs. Ses 6 clés sont un contrat respecté par toutes les fonctions :

_T = {
    "bg":          "#F7F8FC",  # fond de figure et axes
    "texte":       "#1A1C2E",  # titres, labels principaux
    "texte_dim":   "#5C5F78",  # ticks, annotations secondaires
    "grille":      "#D8DAE8",  # lignes de grille, bordures
    "fond_neutre": "#EDEEF5",  # zones de fond secondaires
    "serie_dim":   "#A8ABBC",  # séries estompées, contexte
}
Règle absolue Ne jamais ajouter une 7e clé sans mettre à jour tous les thèmes définis dans themes.py. Si un thème ne définit pas une clé, les fonctions qui la lisent lèvent une KeyError.

Les 4 modules et leur rôle

beau_graphique.py

Le cœur. Toutes les fonctions de graphiques, les helpers privés, PALETTE, _T et bg.init().

narratif.py

Graphiques à message unique (barres_focus, bullet_chart…). Lit le thème dynamiquement via _t().

pipeline.py

Composants de dashboard réutilisables. Appelle les fonctions de beau_graphique.

themes.py

Définition des thèmes nommés. Chaque thème retourne un dict avec exactement les 6 clés de _T.

03 — Fondamentaux

Les paradigmes utilisés

Un paradigme est une façon d'organiser le code — pas un outil, mais un style de pensée. beau_graphique en combine trois, de façon pragmatique.

1 · Procédural — la base

Le code est organisé en fonctions qui s'appellent. Pas de classes, pas d'objets. Chaque fonction reçoit des données, fait quelque chose, retourne un résultat. C'est 95 % du code de beau_graphique.

Avantage concret barres(cat, vals) fait une chose, retourne (fig, ax), n'a pas d'état caché. Tu peux la lire de haut en bas sans suivre l'état d'un objet.

2 · Registre global — configuration partagée

Le dict _T est une variable globale modifiée par bg.init(theme=...) et lue par toutes les fonctions. C'est le pattern "registre" : un état unique partagé en lecture.

# Écriture — une seule fois par session, via bg.init()
bg.init(theme="dark")       # modifie _T et les rcParams matplotlib

# Lecture — dans chaque fonction, au moment du dessin
ax.set_facecolor(_T["bg"])   # lit la valeur courante
Règle critique Seul bg.init() écrit dans _T. Si une fonction de graphique modifie _T directement, elle change le thème pour tout le monde — c'est un bug.

3 · Import dynamique — couplage tardif

Dans narratif.py, le thème est lu au moment de l'appel de chaque fonction, pas au moment de l'import du module. Technique :

# Dans narratif.py
def _t():
    import beau_graphique as _bg
    return _bg._T     # lit _T tel qu'il est maintenant

def barres_focus(categories, valeurs, ...):
    T = _t()                  # lecture du thème à l'instant t
    ax.set_facecolor(T["bg"])  # utilise le thème actif
Pourquoi pas "from beau_graphique import _T" en haut du fichier ? Parce que bg.init() remplace le contenu de _T entièrement. Si tu en avais fait une copie à l'import, ta copie pointerait vers l'ancien objet. En passant par le module (_bg._T), tu lis toujours la valeur courante.

Constantes sémantiques vs index de palette

Distinction critique qui a causé un bug réel :

Type de couleurComment accéderPourquoi
Hausse / positif_COULEUR_HAUTVert = vérité sémantique, indépendante de la palette
Baisse / négatif_COULEUR_BASRouge = vérité sémantique
Série esthétique n°2PALETTE[1 % len(PALETTE)]L'index peut varier si la palette est courte
Couleurs de thème_T["texte"], _T["grille"]S'adaptent automatiquement au thème actif
Ne jamais écrire PALETTE[6] directement. Si l'utilisateur définit une palette de 4 couleurs, PALETTE[6] lève une IndexError. Toujours écrire PALETTE[6 % len(PALETTE)].
04 — Pratique

Ajouter une nouvelle fonction de graphique

Toutes les fonctions publiques partagent le même squelette. Copie-colle ce template et remplis la section "Dessiner".

Le template complet

def mon_graphique(
    categories,
    valeurs,
    titre="",
    sous_titre="",
    xlabel="",
    ylabel="",
    note="",
    figsize=None,
    ax=None,
    format=None,
    background=None,    # toujours en dernier des params standards
    **_extra,              # absorbe kwargs inconnus (pipeline/dashboard)
):
    # 1 — Figure
    fig, ax = _new_fig(figsize, ax, format, background)

    # 2 — Dessin
    couleur = PALETTE[0 % len(PALETTE)]
    ax.bar(categories, valeurs, color=couleur, width=0.6)

    # 3 — Finalisation
    _finaliser(ax, titre, sous_titre, xlabel=xlabel, ylabel=ylabel, note=note)

    # 4 — Retour
    return fig, ax

Étapes

  1. Écrire la fonction dans beau_graphique.py, après les fonctions similaires. Respecter l'ordre des params : titre, sous_titre, xlabel, ylabel, note, figsize, ax, format, background, **_extra.
  2. Utiliser uniquement les couleurs de thème — jamais un hex en dur. Séries : PALETTE[i % len(PALETTE)]. Thème : _T["bg"], _T["texte"]… Hausse/baisse : _COULEUR_HAUT / _COULEUR_BAS.
  3. Écrire au moins un test de fumée (voir ci-dessous) dans le dossier tests/.
  4. Lancer les tests : py -3.11 -m pytest tests/ -v. Si un test existant casse, tu as introduit une régression.
  5. Committer : git add src/beau_graphique/beau_graphique.py tests/<ton-fichier>.py puis git commit -m "feat: ajouter mon_graphique".

Le test de fumée

Un test de fumée vérifie que la fonction s'exécute sans exception et retourne les bons types. Il ne vérifie pas l'apparence visuelle — ça, seul l'œil humain peut le faire.

# tests/test_mon_graphique.py
import matplotlib
matplotlib.use("Agg")   # pas d'écran requis pour les tests
import matplotlib.pyplot as plt


def test_smoke():
    from beau_graphique import mon_graphique
    fig, ax = mon_graphique(["A", "B", "C"], [10, 20, 30])
    assert ax is not None
    plt.close("all")


def test_retourne_tuple():
    from beau_graphique import mon_graphique
    result = mon_graphique(["A"], [10])
    assert isinstance(result, tuple) and len(result) == 2
    plt.close("all")


def test_background_transparent():
    from beau_graphique import mon_graphique
    fig, _ = mon_graphique(["A"], [10], background="transparent")
    assert fig.patch.get_alpha() == 0
    plt.close("all")
Checklist — À faire
  • Toujours return fig, ax
  • Toujours passer par _new_fig() — jamais plt.subplots() directement
  • background=None comme avant-dernier param (avant **_extra)
  • Couleurs via _T[...] ou PALETTE[i % len(PALETTE)]
  • Inclure **_extra pour la compatibilité pipeline
À ne jamais faire
  • Un hex en dur dans le corps d'une fonction : color="#2A2D42"
  • Appeler plt.show() — le notebook décide quand afficher
  • Modifier _T directement depuis une fonction de graphique
  • Indexer PALETTE sans modulo : PALETTE[5]
05 — Pratique

Faire évoluer sans casser

Le risque principal quand on modifie une librairie est de casser le code des utilisateurs qui appellent déjà les fonctions existantes. La règle : ce qui fonctionnait avant doit continuer à fonctionner après.

Tableau des changements

ChangementRisqueRègle pratique
Ajouter un paramètre avec valeur par défautSûrL'utilisateur existant ne passe pas le param — il ne voit rien changer
Ajouter une nouvelle fonctionSûrPas de conflit avec l'existant
Modifier l'apparence interne (épaisseur, marge)SûrL'API ne change pas, seul le résultat visuel évolue
Ajouter une clé à _TAttentionMettre à jour tous les thèmes dans themes.py simultanément
Renommer un paramètre existantCassantGarder l'ancien nom en alias : ancien = ancien or nouveau
Supprimer une fonctionCassantLaisser la fonction avec un message d'avertissement (warnings.warn)
Changer le type de retourCassantToutes les fonctions retournent (fig, ax) — ne pas changer
Modifier PALETTE directementCassantUtiliser bg.init() avec un thème plutôt que modifier la liste

Alias de rétrocompatibilité

# Scénario : renommer "couleur" en "couleur_barre"
def barres(..., couleur_barre=None, couleur=None, ...):
    # Si l'ancien nom est passé, l'utiliser en priorité
    couleur_barre = couleur_barre or couleur

Lancer et lire les tests

# Tous les tests, mode verbeux
py -3.11 -m pytest tests/ -v

# Arrêter au premier échec (pratique pour déboguer)
py -3.11 -m pytest tests/ -v -x

# Exemple de sortie
PASSED tests/test_barres.py::test_smoke                  # ✓
FAILED tests/test_barres.py::test_background_transparent # ✗
AssertionError: assert fig.patch.get_alpha() == 0
# → la condition qui a échoué — commence par lire ça

Workflow git minimal

# Voir ce qui a changé
git status
git diff src/beau_graphique/beau_graphique.py

# Ajouter précisément les fichiers modifiés
git add src/beau_graphique/beau_graphique.py
git add tests/test_mon_graphique.py

# Messages conventionnels (feat/fix/refactor)
git commit -m "feat: ajouter mon_graphique"
git commit -m "fix: PALETTE index hors-limites dans slope"
git commit -m "refactor: thème dynamique dans narratif"
06 — Changelog

Nouvelles fonctions

Ce journal recense les fonctions ajoutées depuis la création de la librairie, avec leur philosophie et leurs paramètres clés.

beau_graphique.py

tendances_comparatives(items, ncols, …)

Graphiques d'investissements temporels style McKinsey. Plusieurs catégories partagent le même axe y. L'année intermédiaire est un point de convergence (cercle ouvert) — pas une barre rectangulaire. Les polygones à 5 sommets reviennent à y=0 aux deux extrémités.

items = [
  {"nom": "IA", "valeurs": [95, 79, 117],
   "deltas": [-17, 48], "cumul": 22, "couleur": "#1B2A8A"},
  …
]
fig, axes = bg.tendances_comparatives(
    items, ncols=4,
    titre="Tech investment 2022–2024",
    sous_titre="Equity, Mds USD",
)
vs tendances_grilletendances_grille = mini-charts indépendants, axes séparés. tendances_comparatives = axes partagés par rangée, style McKinsey exact.
slide(elements, nrows, ncols, …)

Mise en page libre — remplace dashboard() dans une philosophie texte-first. On définit d'abord le discours (titres, paragraphes, callouts, métriques), puis les graphiques viennent illustrer. Chaque élément est placé dans une grille via "pos": (row, col, rspan, cspan).

fig, axes = bg.slide([
  {"pos": (0, 0, 1, 4), "type": "titre",
   "texte": "L'EMEA accélère au T3"},
  {"pos": (1, 0), "type": "kpi", "valeur": "+18%",
   "label": "Croissance", "delta": "vs +11% attendu",
   "positif": True, "couleur": "#2DC653"},
  {"pos": (1, 1), "type": "callout", "couleur": "#F3722C",
   "texte": "L'Allemagne franchit 100 M€ pour la 1ère fois."},
  {"pos": (2, 0, 1, 2), "type": "graphique",
   "fn": bg.barres, "kwargs": {"categories": …, "valeurs": …}},
], nrows=3, ncols=4, figsize=(16, 9))
Typestitre · sous_titre · texte · callout (fond teinté + barre colorée) · kpi · graphique · vide

narratif.py

cascade(categories, valeurs, label_total, …)

Waterfall / bridge chart. Décompose comment des contributions positives et négatives s'accumulent. Le premier élément = point de départ (absolu) ; les intermédiaires = deltas ; l'élément portant label_total = valeur finale. Barres vertes/rouges reliées par des lignes pointillées.

n.cascade(
  categories=["Départ", "Nouveaux", "Churn", "Upsell", "Arrivée"],
  valeurs=[1200, 340, -180, 90, 1450],
  label_total="Arrivée",
  titre="MRR : +250 k€ ce trimestre",
)
pente(categories, valeurs_avant, valeurs_apres, …)

Slope chart — compare N entités entre deux périodes. Les top_n entités à variation absolue la plus forte reçoivent la couleur d'accent et une ligne épaisse ; les autres s'effacent. Flèches ▲/▼ colorées à droite.

n.pente(
  categories=["France", "Espagne", "Italie"],
  valeurs_avant=[72, 61, 55],
  valeurs_apres=[78, 70, 52],
  label_avant="2022", label_apres="2024",
  top_n=1, accent=ACCENTS["orange"],
)
nuage_annote(x, y, labels, tailles, focus, …)

Scatter annoté avec bulles optionnelles et quadrants. Chaque point est étiqueté. Les points en focus reçoivent l'accent (gras, plein) ; les autres s'effacent (gris, semi-transparent). quadrants=True trace les médianes x/y avec des libellés de cadrant.

n.nuage_annote(
  x=[22, 45, 78], y=[3.2, 1.8, 4.5],
  labels=["A", "B", "C"],
  tailles=[100, 200, 500], focus=2,
  quadrants=True,
  quadrant_labels=("Faible/Fort", "Fort/Fort",
                   "Faible/Faible", "Fort/Faible"),
)
07 — Maintenance

Journal des pièges

Ces cinq bugs ont été détectés et corrigés durant le développement de beau_graphique. Comprendre leur cause racine te permettra de les repérer avant qu'ils ne se reproduisent.

Bug 01 PALETTE[n] — IndexError avec une palette courte
SymptômeIndexError: list index out of range dans slope() à la ligne couleur_hausse = PALETTE[6].
CauseL'utilisateur avait remplacé PALETTE par une liste de 4 couleurs Orange. L'index 6 n'existe plus dans une liste de longueur 4.
FixUtiliser le modulo : PALETTE[n % len(PALETTE)]. Pour des couleurs sémantiques (hausse/baisse), utiliser _COULEUR_HAUT / _COULEUR_BAS à la place de tout index.
DétecterChercher PALETTE[ dans le code source. Chaque occurrence sans modulo est un risque latent.
Bug 02 Couleurs hardcodées — le thème est ignoré
SymptômeEn thème dark, certains éléments restent en gris clair ou fond blanc — graphique illisible sur fond sombre.
CauseDes fonctions (heatmap, waterfall, _dessiner_kpi) avaient des hex en dur dans leur corps : color="white", color="#6B6F85".
FixRemplacer par les clés de thème : _T["bg"], _T["texte_dim"], _T["grille"]. Pour hausse/baisse : _COULEUR_HAUT / _COULEUR_BAS.
DétecterChercher les chaînes de forme #XXXXXX dans les corps de fonctions (pas dans les constantes du haut du fichier).
Bug 03 transform mixte — labels hors zone + tight_layout cassé
SymptômeLabels du bullet_chart apparaissant très à gauche, hors du graphique visible. Warning tight_layout : falling back to Agg renderer.
Causetransform=ax.get_yaxis_transform() crée un système mixte (x en fraction d'axes, y en données). Matplotlib ne peut pas calculer les marges pour des éléments placés en dehors de l'espace connu des axes.
FixPlacer le texte en coordonnées de données et étendre xlim pour créer la zone gauche :
ax.text(-xmax * 0.02, 0, label, ha="right")
ax.set_xlim(-xmax * 0.32, xmax * 1.05)
DétecterWarning tight_layout lors du rendu, ou labels invisibles sur un graphique multi-axes.
Bug 04 narratif.py — thème ignoré après bg.init()
SymptômeAprès bg.init(theme="dark"), les fonctions de narratif continuaient à dessiner sur fond blanc.
Causenarratif.py avait des constantes au niveau module : BG = "#F7F8FC". Elles étaient figées au chargement du module, avant tout appel à bg.init().
FixSupprimer toutes les constantes couleur. Ajouter _t() qui fait import beau_graphique as _bg; return _bg._T et l'appeler en début de chaque fonction narratif.
DétecterChercher les constantes couleur au niveau module dans tout fichier qui n'est pas beau_graphique.py. Si elles ne viennent pas de _T, elles ne suivront pas le thème.
Bug 05 Multi-axes — background ignoré sur les sous-graphiques
SymptômeLa figure globale de facet() avait le bon fond, mais chaque sous-graphique restait blanc.
Cause_appliquer_background n'était appelé qu'une fois sur la figure. Les axes créés par fig.add_subplot() ne reçoivent pas automatiquement le fond de la figure.
FixAppeler _appliquer_background(fig, None, background) une fois pour la figure, puis _appliquer_background(fig, ax_i, background) dans la boucle de création de chaque axe.
DétecterToute fonction qui crée des axes avec add_subplot() ou gs[i, j] doit propager background sur chaque axe.
